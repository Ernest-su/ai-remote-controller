# 仅清理应用缓存

在应用管理页选择用户应用的“清理缓存”，核对包名、版本和 Android 用户后确认。缓存可能包含离线下载，清理后应用需要重新下载或生成内容。提案绑定准备时的连接，切换设备或重连后须重新准备。确认前取消不会执行；确认后是不可取消的包管理器任务，断线不能撤销已提交操作。

服务只调用系统明确声明的 `--cache-only` 接口，并指定已确认的用户；不会退回不带该选项的数据清除命令。需要明确的 INTERNAL_DELETE_CACHE_FILES 权限以及 shell/root 身份；目标 shell 缺少该权限时提前拒绝，未知/旧系统无此能力时拒绝。系统及特权应用不提供清理，root 不绕过这项限制。

模型只能准备提案，通过“查看模型待确认的缓存清理”逐项审核。提案十五分钟过期，不跨服务重启保存；确认时与任务提交前重新核对应用身份，变化时要求重新准备。接口成功表示包管理器报告完成，不统计释放空间，也不能证明任意应用的数据完整性。

只读存储分析仍在目标文件页，不把 APK、日志或下载文件按后缀自动视为缓存；这些文件沿用逐项文件删除确认。此功能不包括全系统一键加速、进程结束或内存清理。

正常 App/JVM 部署流程现支持目标的 UID＋shell su 语法。需要缓存内部权限时，可由用户在运行权限页选择优先 root 并重启/部署服务；权限仍通过实际 caller 探测，清理缓存入口本身不自动提权。

清理进度始终绑定确认返回的原任务、包名及缓存清理类型；响应对象不匹配时显示错误，不报告完成，也不继续查询其他任务。
