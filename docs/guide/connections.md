# 连接目标设备

打开设备页会自动查找当前 Wi-Fi 网段的 ADB 设备（默认端口 5555）并发现已运行的遥控服务。历史、局域网服务与 ADB 结果按地址合并到同一列表，用小图标和“已保存 / 局域网服务 / ADB”文字标明来源，当前连接单独标识。点击设备右侧连接；已发现服务优先直连，否则通过保存记录或 ADB 部署。服务连接失败时自动通过目标 IP 的 ADB 端口（未保存时使用 `5555`）尝试部署，并提示进度；目标可能需要批准 RSA 授权。自动部署失败会显示原因、展开“连接目标设备”，并填入目标 IP、ADB 端口和服务端口，便于修改或切换无线调试配对。已保存项右侧“管理”可修改显示名或忘记记录。

右上方刷新按钮重新扫描。扫描只确认 ADB 协议响应，不自动授权、配对或安装程序；未发现不代表设备离线。没有 Wi-Fi 时显示提示；大于 1024 地址的网络仅扫描当前 /24 并标注范围。非默认端口及需配对的无线调试仍可展开“连接目标设备”手动填写。离页或后台停止扫描，返回页面重新扫描。

控制手机上的 ADB 连接用于首次安装和后续程序管理。独立 runtime WebSocket 用于日常遥控，两者是不同通道。

## TCP ADB

点击右上角连接状态进入“设备”，选择 TCP，填写目标 IP/主机名、目标已启用的 ADB 端口和遥控服务端口，然后点击“连接并部署”。默认 ADB 端口为 `5555`，请以目标实际端口为准。首次连接可能需要在目标屏幕批准 RSA 授权。

应用不会通过 USB 为目标启用 TCP ADB，也不提供控制手机本机配对。

## 六位配对码

在目标的无线调试页面打开使用配对码配对的入口。在手机选择“配对码”，输入目标 IP、配对端口及六位配对码。

配对端口与无线调试首页的连接端口不同。连接端口留空时，应用按已配对 GUID 自动发现 `_adb-tls-connect._tcp.`；网络无法转发 mDNS 时，可选填目标首页显示的连接端口。

## 二维码

在手机选择“二维码”并开始配对，使用目标设备无线调试中的二维码扫描入口扫描手机显示的二维码。手机生成临时会话名称和密码，发现目标临时配对服务后建立 TLS 连接。

目标系统必须提供无线调试二维码扫描能力；相机扫描行为和厂商配对界面需在对应设备上验证。

## 设备历史与局域网发现

成功 ADB 连接会保存设备记录，即使随后部署失败也保留。配对码和二维码密码不会持久保存。设备端报告稳定 UUID 后，记录会合并为该身份。

历史重连优先连接健康 runtime；需要 ADB 时按 GUID 查找最新连接端口，再尝试保存的端点。目标无线调试端口变化通常不需要重新配对。

统一列表中的“局域网服务”来源是目标二进制发布的 `_airc._tcp.` 服务，直接连接其 WebSocket。这不是 ADB mDNS 发现。mDNS 通常限于同一子网；跨 VLAN、VPN 或隔离 Wi-Fi 需要网络支持。

## 设备端 root 权限

在功能网格的“运行权限”页打开“优先使用 root 权限”，设置会保存在控制手机，默认关闭。通过 ADB 部署时先检查当前 adbd 用户，再验证 `su -c id -u`；能获得 root 则以 root 启动，被拒绝、不存在或授权等待超时则回退到 shell。目标 root 管理器可能需要批准 ADB shell 的授权。应用不会为设备获取 root，也不会重启 adbd。

已有选中设备时，切换开关会通过 ADB 应用设置并重新连接服务；尚未选择设备时，下次 ADB 部署应用。仅通过局域网发现且没有保存 ADB 信息的设备，需先在设备页连接 ADB，再点击“检查 / 安装版本”。仅重连健康局域网服务不会改变其权限。设置页的“当前运行权限”来自目标实际 UID；未获得有效 UID 时显示未知。

关闭后停止 root 服务，恢复配置与状态文件的 shell 所有权，再使用 shell 启动，设备身份和模型配置保持不变。更新失败会尝试恢复旧版本、原权限和原端口。权限切换及旧 shell 服务的回滚需要目标支持 `su 2000 -c`；不支持时保留旧服务并显示错误。原服务为 root 而授权后来被撤销时，需要恢复 root 授权才能管理，不会假装已停止或回退成功。

root 模式下，遥控工具和模型调用的工具以 root 执行。协议不提供登录鉴权，高影响管理动作使用各自确认流程；应仅用于可信局域网。

设备页将已保存、局域网服务与扫描到的 ADB 合并在同一列表，手动连接默认折叠。遥控器首页的弹性状态区切换显示执行反馈与播放状态，并提供媒体播放和静音按键；功能菜单取消独立媒体控制入口。

开发者可直接调用只读 [`device.info`](../reference/tools.md#device-info) 查询目标型号、系统、ABI、屏幕和存储，也可让模型调用。在功能菜单的「设备信息」页点击「刷新设备信息」即可查看；缺失或无权限的字段显示未知。

## 设备显示名

设备页可修改本应用中的显示名（1–64 个字符）。名称按设备身份保存，重连后保留，不修改目标系统名称。手机的“忘记”会删除该设备记录与显示名；手机和桌面分别保存自己的名称。

## 分阶段网络诊断

设备页的“诊断服务连接”检查填写的目标地址与服务端口；未填写时使用当前设备的地址。卡片显示实际探测地址、逐阶段耗时和通过、失败或未检查状态，可取消诊断。

- ADB：只查询属于该目标的已有授权会话身份，不自动连接、配对或部署。未提供会话则跳过，局域网直连无需 ADB。
- runtime HTTP：读取 `/status` 并校验协议。无法解析地址、连接失败、超时或协议不兼容会提供对应处理建议。
- WebSocket：使用独立探测连接执行握手和协议校验（包含一次独立状态查询），不发送遥控指令，不改变当前控制连接。HTTP 失败时先修复 HTTP，跳过这一阶段。
- mDNS：Android 在最多五秒内观察匹配地址/端口的公告；未观察到只表示未完成检查，不等于服务离线。桌面创建独立的 JmDNS 发现实例，按通往目标的 IPv4 接口探测，匹配地址、服务端口及协议；阶段预算为 12 秒，包含发现和关闭实例。TCP ADB 使用设备 IP 与实际服务端口，USB ADB 没有局域网地址时仍显示未检查。

这是控制端连接链路诊断，不是目标网络加速或测速；阶段成功不能保证后续一直可达。手动连接与组播发现相互独立，mDNS 不可用时仍可使用准确地址连接。

设备信息查询绑定发起时的连接，切换目标后旧排队查询被拒绝；在当前设备页刷新获取信息。

## 设备提示语言

连接时会把遥控 App 的当前语言传给被控端，中文 App 使用中文设备错误提示，其他语言使用英文。更改 App 语言后重新连接即可生效；同一目标的不同控制端可分别使用各自语言。uinput 版本不足、缺少 root 或设备接口不可用等能力限制会按此语言提示，未知系统错误保留原始技术详情。
