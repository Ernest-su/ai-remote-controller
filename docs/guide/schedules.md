# 定时操作

从「功能 → 定时操作」管理当前被控设备上的任务。任务数据保存在被控端；手机遥控器退出不会影响已保存任务的定时执行。

## 创建任务

点击「新建定时操作」，选择执行时间：

- **倒计时**：通过下拉列表选择 15、30、60、90 分钟，或 1、2、3 小时后执行；60 分钟与 1 小时为同一选项。
- **单次**：只通过时间选择器选择执行时间，无须选择日期。按被控端本地时间，今天尚未到则在今天执行；已到或已过则在明天执行，只执行一次。页面和保存确认框会显示具体执行日期与时间。
- **每天固定时间**：通过时间选择器选择每天的执行时间，每天执行一次。

选择器采用 24 小时制，点击确定才更新草稿，返回则取消本次选择。切换执行时间方式保留各自的时间草稿。

时间以页面显示的**被控端本地时间**为准，手机和电视时区不同也不会按手机时间换算。若停留在确认框期间错过了单次执行时间，被控端会拒绝保存，请返回后重新确认下一次时间。

执行动作通过下拉列表选择，可选「关闭屏幕」「暂停播放」「调节媒体音量」「静音」「解除静音」「关机」「退出应用」「打开应用」。调节媒体音量时输入 0–100 的整数百分比，被控端按设备支持的档位取最接近值，静音状态遵循设备系统行为。静音和解除静音只作用于媒体声音，使用明确的静音/解除指令，重复执行不会反向切换；解除静音后的音量遵循系统恢复规则。「关闭屏幕」复用标准遥控器的屏幕电源接口，只关闭物理显示，不关机、不改变播放状态、不自动开屏；不支持的设备显示执行失败，可通过标准遥控器重新打开屏幕。控制端前台每3秒回读服务的屏幕模式，切换前也会重新读取，避免定时关屏后按旧状态操作。这些音量操作不修改铃声、闹钟或通话音量；固定音量、音量保护或系统限制导致无法达到设定状态时，任务详情显示失败原因。暂停通过当前优先的正在播放且支持暂停的 MediaSession 提交，不会切换为继续播放；没有符合条件的会话时明确失败。应用从被控设备列表选择；退出应用使用强行停止，可能丢失未保存内容，不支持系统和特权应用。关机需要被控端服务以 root 运行，并具备对应系统权限和框架接口；保存时与执行前都会检查，不能获得权限时明确失败。

保存前核对目标设备、动作、应用和时间并确认。确认只适用于发起时的连接，切换设备或重连后需要重新确认。定时任务不向模型暴露创建、启用或确认接口。执行时如果应用安装、版本或 Android 用户发生变化，会失败并要求重新创建任务。

## 每天重复任务的运行条件 {#daily-requirements}

由于运行限制，每天重复的任务需要在被控设备开机后，手机遥控器连接过被控设备以启动遥控服务，或者被控端遥控服务仍在后台运行。

- 关闭手机 App 或断开手机连接，不会停止被控端的调度。
- 被控端关机、重启后尚未启动服务、系统终止服务期间，无法执行任务；不支持定时开机，也不保证唤醒休眠设备。
- 服务恢复时保留任务数据，跳过已经错过的单次执行；每天任务重新安排到下一个时间点，不补执行过去的动作。
- 正在运行的服务若错过超过一分钟，也会跳过该次执行。设备时间应保持准确。
- 服务在提交操作后异常退出，结果可能不确定；恢复后不自动重试。界面显示「已提交操作」不代表画面或设备最终状态一定已改变。

## 编辑、查看、立即执行、暂停和删除

点击任务的「编辑」可修改时间方式、执行时间、动作、应用或媒体音量，表单预填已保存的原值；若任务没有保存倒计时长度，需重新选择倒计时时间。确认「保存修改」后原位替换同一个任务，保留启用或暂停状态，清除原来的执行结果；不会新增重复任务。倒计时从保存时重新计时，单次时间按被控端最近的未来所选时刻重新计算。保存失败保留草稿，取消不修改被控端任务；切换设备或重连后关闭旧任务编辑，避免误改其他设备。执行中的任务暂不允许编辑。

列表显示是否启用、下次执行时间、上次状态及可展开的执行详情。暂停不会删除任务；过期的单次任务可编辑为未来时间后重新启用，也可重新创建；每天任务可重新启用。删除只移除未来的调度，已提交的动作不会撤销。执行期间不允许删除或切换启用状态。每台被控设备最多保存100项，完成的任务可手动删除。

页面每10秒静默更新任务状态，保留列表位置、展开的详情和编辑草稿，后台刷新不显示全页进度条或禁用操作。手动刷新期间仅禁用刷新按钮。

每条任务提供「执行一次」：确认目标设备及具体动作后立即提交，暂停或已完成的任务也可使用，不会重新启用或改变原来的未来执行时间。执行中禁止重复提交；若原计划时间恰好在本次执行期间到达，该次计划跳过，避免重复执行。结果显示在同一条任务的执行详情中，失败或超时不自动重试。

手机与 JVM 桌面使用相同的被控端任务列表。离线时可查看功能和编辑非敏感草稿，连接后才能读取、保存或管理任务。
