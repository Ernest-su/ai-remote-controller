    媒体投送¶

    在“文件管理”页选择图片、音乐或视频，先完成上传，再点击文件条目的“在被控设备播放”。App 查询目标实际声明的播放器，展示来源、MIME 类型和包名。选择播放器后点击“用目标播放器打开”；查询本身不会启动播放。

    Downloads 文件使用本地文件 URI；服务收件箱及全盘范围通过 Rust 二进制服务的临时 HTTP 媒体地址提供内容，避免要求播放器读取服务私有目录。播放器是否支持这两种来源可能不同，Android 占位处理器不算可用播放器。没有匹配播放器时提示不可用，可在目标安装支持该来源的播放器，或把文件放到可供播放器访问的 Downloads 中。

    支持 PNG、JPEG、WebP、GIF，MP4、WebM、MKV，以及 MP3、M4A、WAV、Ogg、FLAC 的类型选择；扩展名只用于选择 MIME，不证明内容可解码。具体格式、编码、DRM 和网络策略由目标播放器决定。工具返回“播放器已启动”仅证明 Android 启动请求成功，实际显示/播放请查看目标画面与播放状态。

    私有媒体地址提供 GET/HEAD 和单段 Range 请求，按 64 KiB 缓冲读取，支持播放器请求片段与拖动，不把文件转成 Base64。每份资源最多四个同时读取，最多保留四份资源；连续 24 小时没有访问后过期，进程重启后失效。新投送可能淘汰未在读取的旧资源。文件内容变化会拒绝继续读取，需要重新打开。控制端可点击“释放服务媒体流”，关闭此资源的后续读取；目标文件保留，已经被播放器缓存的内容可能继续显示。

    这属于文件投送，不是实时屏幕镜像。断开控制连接不等于关闭目标播放器；服务媒体资源仍按访问期限管理。切换设备时 App 清空旧播放器选择。

    文件预览中“在主控设备播放”使用控制端播放器，与本页的被控设备播放相互独立。图片、文本与主控端播放的操作见文件预览。

    播放器兼容性¶

    部分播放器虽然声明支持 HTTP，实际仍可能把地址当作本地路径处理；也有播放器仅支持本地文件。HTTP 媒体流无法打开时，可改用本地播放副本或选择其他支持该来源的播放器。系统声明、Activity 启动和 MediaSession 状态都不能代替实际解码与画面检查。

    私有文件的本地播放副本¶

    新版服务可在“在被控设备播放”中选择“本地播放副本”，先查询本地文件播放器。点击“创建副本并用目标播放器打开”，核对公开可读范围和占用空间，再确认创建。服务用固定 64 KiB 缓冲将原文件复制到 Downloads 下的独立 .airc-media-<UUID>/ 目录，重新读取副本校验 SHA-256 后才打开播放器。原文件保留，已有文件不覆盖；目录内有 .nomedia，避免普通媒体扫描加入相册。

    界面显示准备、校验和字节进度，提供取消。失败或取消清理本次创建的文件；“释放播放资源”删除播放副本并保留原文件。若副本文件被其他人替换为另一文件，清理会保留替换项。副本仍可被有 Downloads 权限的其他应用读取，因此不会在查询播放器时自动创建。

    最多四份在准备或保留的副本，上传/下载/发布共用最多两个活动任务。需要额外磁盘空间，服务保留至少 16 MiB 余量。副本记录以私有权限持久化，服务进程重启后恢复未过期的已完成副本，并按记录清理未完成副本；24 小时过期副本在启动或下一次发布时清理。点击“查看保留的播放副本”可逐项释放恢复的记录。身份不匹配、损坏记录或存储不可访问时保留文件并报告恢复问题，不按文件名扫描删除。整机重启后的存储身份变化及断电窗口未完成实机验收，请在播放结束后主动释放。只有确认副本准备成功后才发送播放器打开请求；创建副本不等于媒体可解码。

    音视频格式、编码、DRM、网络来源与固件媒体组件需分别验证；某个播放器能处理测试文件，不代表所有播放器、文件或扬声器输出都可用。播放失败时先核对来源与格式，再选择其他目标播放器。

    播放位置与时长¶

    Android 从遥控器右上角类型选择页打开“播放控制”（JVM 桌面仍从功能菜单进入），点击“刷新播放会话”，选择目标包与会话，查看播放器报告的位置和时长。可拖动进度条，前后跳转 10/30 秒，或填写分:秒（如 12:30）、时:分:秒后跳转。位置和时长按可读时间显示；只有位置和时长已知时才显示可拖动进度条。超出已知时长、播放器未声明定位支持、离线或接口不可用时禁止提交。位置草稿在导航和旋转后保留。

    提交成功只代表定位请求送出。界面随后查询实际位置，明确区分观察到的位置和尚未更新；也可手动刷新。标准接口或权限不受目标支持时显示不可用，原遥控器播放键仍可使用。应用不会把左右键或快进键当作精确定位，也不虚构未知时长。多会话需选择可区分的会话；匹配不唯一时拒绝定位。

    播放器自定义动作¶

    在“播放控制”刷新会话并选定播放器后，仅展示该会话通过标准 MediaSession 声明的动作名称。点击可提交选集、清晰度等播放器实际提供的动作；没有声明时不生成相关按钮。当前只发送动作 ID，不猜测私有参数 Bundle；依赖额外参数的动作可能无法生效。提交后刷新会话，仍需核对播放器实际结果，接口成功不等于选集或清晰度已经改变。离线或进行请求时禁用。

    媒体操作绑定开始时的连接。创建播放副本期间断开或重连后，进度查询、播放器启动和清理请求不会转发到新连接。原服务可能仍保留副本；重新连接后使用“查看保留的播放副本”核对并释放。

    播放定位和已声明自定义动作在单次提交及其后续状态核对中沿用同一连接；连接改变后停止旧操作核对，并报告错误。已提交到播放器的动作不会因断开而撤销，可重连后刷新状态核对。

    播放副本准备与取消固定查询原任务 ID；进度或取消响应对象不匹配时显示错误，不启动播放器，也不据此释放其他副本。

    释放资源需要目标明确返回 released=true。响应缺失或未确认时显示错误，保留本地资源记录供重试，不提示已释放。

    播放器启动响应必须与所选包名、文件路径、MIME 和传输方式一致；错配时显示错误，不提示已启动。启动成功仍不代表内容已实际播放。

    准备播放副本的任务必须匹配所选文件范围，进度不能超过文件长度；副本名称和长度也需一致。对象或进度错配会报告错误，不打开该副本。

    完成的播放副本可在服务正常重启后通过“保留的播放副本”重新查看并释放；准备任务本身不会恢复，源文件保留。正常重启恢复不等于断电恢复保证，异常断电后应重新核对副本与原文件状态。

    保留副本列表会校验 ID 唯一性、标准副本路径和 1 TiB 协议大小上限。异常响应不会替换已有记录；重新读取后再释放副本。

    播放器候选若包含重复或无效包名，会清除选择并报告错误，重新读取候选后再投送。

    播放定位使用非负整数毫秒；输入格式错误或超过播放器报告时长时，输入框会说明原因并禁用提交。播放器未声明定位能力时仍可阅读会话信息。媒体来源选择在窄屏自动换行，未找到播放器时显示处理建议。
