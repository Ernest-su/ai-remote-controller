    配置模型服务¶

    从功能网格进入“模型配置”。App 按 API 根地址记录多套配置，可切换、删除，并独立手动更新到当前连接的目标设备。

    保存与切换¶

    填写 API 根地址、API Key 和模型名称，点击“保存到 App”。相同地址（忽略末尾 /）更新同一条配置；不同地址分别保存。点击已记录的地址切换，点击“新增配置”开始填写另一套。删除同时移除该本地配置及其缓存模型列表，已经更新到目标设备的配置保持不变。

    API Key 默认以密文显示，可点击“显示 / 隐藏”切换。页面重建后恢复隐藏。配置、密钥与缓存使用 Android Keystore AES-GCM 加密后保存到 Android App 私有存储，不进入 Android saved state，不写入仓库或日志。卸载 App 将失去这些本地配置；它们不是系统备份中的可迁移密钥。

    拉取与选择模型¶

    填入 API 地址与 API Key 后，点击“拉取 / 更新模型列表”，控制手机请求该地址下的 /models。成功后按地址缓存并保存配置，列表去重排序；没有模型列表接口或请求失败时仍可手动输入模型名称，已有缓存保留。更换地址或 API Key 后，当前草稿不沿用旧凭据的缓存。

    模型名称可直接输入，也可点击“从缓存列表选择模型”。列表不会自动刷新；刷新是手动操作，保存和切换配置都不会发起模型请求。

    API 根地址例如 https://provider.example/v1，支持 HTTP(S)，不得包含 URL 凭据、查询参数或片段；重定向不会携带密钥跳转到另一个地址。目录响应上限 1 MiB / 2000 个条目。

    手动更新目标¶

    目标未连接时，页面会说明本地配置仍可管理；连接目标后，点击“更新到目标设备”。这个操作保存当前 App 配置并将地址、密钥和所选模型发给当前目标；本地保存、切换、删除和拉取列表均不会自动修改目标。更新期间目标连接改变时拒绝发送，重新连接后可重试。

    目标直接访问模型服务，因此目标自身必须能解析地址、建立连接并使用密钥。提供商需要兼容 /chat/completions 的 tool_calls；列表中出现某个模型不保证它支持工具调用。无需录音、转写接口或识别模型。

    目标配置仍以 0600 权限保存到目标状态目录，状态接口不返回密钥。按键、应用等直接工具不依赖模型配置。旧配置中的识别模型字段会被忽略；同步只包含 API 地址、密钥和模型名称。

    JVM 桌面端共用模型编辑组件、配置控制器和目录客户端，保存到当前桌面用户的私有加密文件；与手机的 Android Keystore 配置分别管理，见桌面指南。

    开发调用方可为单次模型任务限定工具范围；新服务会过滤可见工具并在执行前再次检查。真实只读模型验收要求服务显式支持该能力，不能仅靠提示词或旧服务声称“只读”。普通 App 文本任务的默认工具范围保持原有行为。

    点击保存后继续编辑模型名称，进行中的保存仅保存点击时的配置，不会覆盖后来输入的草稿。需要保存新的名称时再次点击“保存到 App”。

    模型列表缓存写入期间继续修改模型名称，返回结果会保留新名称及拉取的列表；缓存写入保存的是当时的名称，新名称仍需主动保存。

    删除配置按规范化 API 地址识别当前草稿；地址尾斜杠不会形成不同配置。删除当前配置会取消其待完成的模型列表拉取，迟到结果不会恢复已删除配置。

    本地保存、切换和删除按发起顺序进入写入队列；快速保存后删除时，排队的旧保存不会在删除后恢复配置。

    保存、切换和删除统一使用规范化 API 地址，忽略首尾空格和尾斜杠；相同地址保留对应的模型列表缓存。无效地址的切换或删除请求会显示错误，不修改配置。

    “更新到目标设备”绑定点击时的实际连接。保存本地配置期间若切换设备或重连同一地址，旧更新会失败，本地配置保留；需在新连接上再次主动点击更新。发送前后均核对连接代次。
