    设备端服务与更新¶

    功能网格的“服务管理”以“管理服务”卡片展示服务端版本、GitHub 在线版本入口、检查/安装、状态查询、重启和停止；完整输出按需展开。管理操作需要目标 ADB 可访问；应用会根据设备记录建立管理连接。

    内置版本¶

    首次通过 ADB 连接部署时使用 APK 内三 ABI 的设备端资产。安装器按目标 ABI 选择程序，校验大小与 SHA-256、执行 --version。目标摘要和运行权限均相同时不重复推送或重启。

    部署和重启先传输并校验临时脚本，再通过短命令执行，兼容 ADB 单包上限为 4096 字节的旧设备。脚本无输出时提示连接可能中断；重新连接后先查询服务状态，再决定是否重试。

    停止旧服务和替换程序前会检查目标端口。属于当前状态记录且进程身份有效的服务允许正常更新；其他占用会中止部署并显示端口检查错误，保留原服务与程序。若程序或状态目录曾被删除，旧进程仍可能运行并占用端口；切换 root 开关不能解除占用。通过 ADB 核实监听进程后，以该进程所需的权限停止它（root 进程需要 root），再重新部署。不要通过删除状态目录处理此问题，以免丢失设备身份和模型配置。

    在线版本¶

    在线源固定为项目 GitHub 仓库，界面不再要求填写清单地址或保存更新源。点击“检查 / 安装在线版本”获取仓库最新 Release 的 manifest.json 和 manifest.json.sig，验签后下载清单中对应 ABI 的程序。GitHub 最新资产下载入口采用官方的 releases/latest/download/文件名 约定。

    Release 必须提供完整的签名资产；缺少 Release、清单或有效签名时明确报错，不回退到未签名文件。应用保留固定公钥、协议、应用版本范围和大小/摘要核对。发布准备见准备发布。发布 workflow 生成草稿 Release；维护者公开后才进入在线更新入口，草稿不能用于在线更新。

    取消与恢复¶

    下载可以取消，未完成文件会清理。开始替换目标程序后，安装器先完成候选就绪检查或旧版本恢复，再结束取消操作。候选启动失败时恢复旧文件及原服务端口。

    ADB 提交中断、SIGKILL 或断电后应重新核对目标服务与文件状态，不能仅凭断线判断更新或回滚已完成。详情见协议与后台管理。

    服务权限检测同时支持 su -c 与目标常见的 su 0 sh -c；只有实际 UID=0 的探测结果才选择 root 管理。关闭优先 root 时，已有 root 服务仍由已验证管理权限处理，然后明确以 UID2000 启动；没有可靠降权路径时在停止原服务之前拒绝。切换 root 时只调整私有 framework 适配目录所有者，切回 shell 沿用状态权限归一化，保留设备身份和配置。

    停止目标服务前会提示遥控连接将断开；确认「停止服务」才执行，取消不改变服务。查询、安装和重启的完整输出可在「查看操作详情」中展开。

    服务管理需要目标记录中已有已授权的 ADB 连接；仅通过局域网服务发现的设备应先在设备页完成 ADB 连接，相关管理按钮才可使用。

    普通连接和历史重连会先核对当前控制端配套版本与正在运行的二进制 SHA-256，不匹配时自动部署并复核；不以版本号相同作为复用依据。更新失败保留错误并停止连接，详见连接说明。
